Task: generate one complete Java unit test class using the focal class and project metadata in the Context JSON.

Hard requirements:
- Return Java source code only.
- Return exactly one Java compilation unit.
- The package declaration must exactly match Context JSON field `package_name`: {package_name}
- The only public top-level class must exactly match Context JSON field `required_generated_class_name`: {required_generated_class_name}
- Do not return, rewrite, summarize, or modify the focal class.
- Do not output production code.
- Do not output `pom.xml`, Gradle files, dependency changes, patches, or unified diffs.
- Do not include markdown fences, explanations, comments outside Java code, or multiple files.
- Use the detected build tool from Context JSON: {build_tool}
- Use the detected test framework from Context JSON: {testing_framework}
- Include all imports required by the detected framework. For junit5 use `org.junit.jupiter.api.Test`, lifecycle imports such as `BeforeEach`, and `org.junit.jupiter.api.Assertions`; for junit4 use `org.junit.Test`, lifecycle imports such as `Before`, and `org.junit.Assert`.
- Use only APIs, constructors, methods, imports, and dependencies visible in Context JSON.
- Prefer project-compatible imports and assertions over modern APIs that may not exist in the project.
- Prefer a small deterministic test that compiles over a broad fragile test.
- Derive expected outcomes from the focal class's public behavior and the project context; do not invent an oracle that is unsupported by the available code.
- For each test scenario, include at least one behavior-specific assertion over an observable return value, state change, or side effect.
- Cover boundary values and exceptional behavior when they are supported by the public contract or implementation context.
- Avoid weak or tautological assertions such as `assertNotNull` used as the only oracle, `assertTrue(true)`, comparisons of a value with itself, or assertions over constants unrelated to the executed behavior.
- Prefer exact or semantically meaningful expected values over assertions that merely confirm that execution completed.

When existing tests are provided in Context JSON, mirror their framework style, imports, and assertion library, but do not copy the original test verbatim.
